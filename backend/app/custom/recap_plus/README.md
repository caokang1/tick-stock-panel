# 复盘补充数据（recap_plus）

面板自带的 AI 复盘只把指数、涨跌家数、板块排名交给 AI。这个扩展在后面再接一段材料，让复盘可以写到榜单、
行业涨跌停、两融和自己的持仓。复盘页、定时复盘、归档、推送都还是面板原来的，这里只管“多给 AI 一些数据”。

## 多给了哪些数据

| 内容 | 来源 |
|---|---|
| 沪、深成交额及较前一日的变化 | 本机日线 |
| 成交额前十、总市值前十 | 本机日线、股票资料里的总股本 |
| 各行业的涨停、跌停家数和代表股票 | 本机日线、行业归属表（东方财富行业，不是申万一级） |
| 全市场两融（融资余额、融资买入额等） | 东方财富数据接口，联网 |
| 每只持仓的数量、成本、盈亏、近 5/10/20 日表现 | “持仓提醒”里登记的持仓、本机日线 |
| 每只持仓的市盈率、市净率、市值 | 腾讯行情接口，联网 |
| 每只持仓的主力资金流向、两融 | 东方财富，联网 |
| 对标股票当天的涨跌 | 本机日线 |

哪一块没有取到，材料里会明说，并要求 AI 写“未取得”，不要编。

## 联网的规矩

- 每个请求都经过限流器（记在东方财富、腾讯行情两个来源名下），一个一个发，不并发。
- 东方财富有一个请求没成，后面发往它的请求就不再发，也不重试、不换别的入口。
- 一次复盘大约发 `1 + 持仓数 × 2 + 1` 个请求（8 只持仓约 18 个）；资金流向最多取 12 只。
- 同一个交易日取到的结果存在 `data/user_data/extensions/recap_plus/cache/`，当天重跑复盘不重复请求。

## 设置

- **持仓**：在面板的“持仓提醒”页登记，这里直接读。
- **对标股票**：`data/user_data/extensions/recap_plus/config.json`，例如
  `{"peers": {"000001.SZ": ["600000.SH", "600036.SH"]}}`。目前没有页面，要手改这个文件。
- **复盘写成什么样**：由复盘页里的“提示词”决定（面板原有功能）。要让 AI 写持仓、给操作建议，需要在提示词里写明。

`GET /api/custom/recap-plus/preview` 可以看到会交给 AI 的这段材料原文。

## 对面板核心文件的改动

`backend/app/services/market_recap.py` 加了一个入口：拼材料时如果装了这个扩展，就把它返回的文字接在后面。
没装或者出错时为空，原来的复盘不受影响。
