# Claude 转接口（community.claude-bridge）

把本机的 `claude` 命令行包装成一个“OpenAI 兼容接口”，让面板的 AI 功能（盘后复盘、个股分析、财务分析等）
不用另外申请 API Key，直接用本机已经登录的 Claude。

## 怎么用

1. 确认本机装了 `claude` 命令行并且已经登录（终端里运行 `claude` 能正常对话）。
2. 打开 `GET /api/custom/claude-bridge/info`（在浏览器里访问面板地址加这段路径即可），里面有三样东西：
   `base_url`（接口地址）、`api_key`（转接口令）、`model`（模型名）。
3. 到面板的“设置 → AI”，选 OpenAI 兼容接口，把这三样填进去保存。

模型填 `claude-cli` 表示用命令行的默认模型；也可以填 `sonnet`、`opus`、`haiku` 这样的别名。

## 用之前要知道的

- **用的是本机 claude 登录的那个账号**：每次调用都算它的额度，发过去的内容也经过这个账号。
  如果是公司的账号，请先确认公司允许这样用。
- **不支持工具调用**：AI 助手里需要它自己去查数据的对话做不了，只能纯聊天；复盘、分析这类
  “给材料、写报告”的功能不受影响。
- **比直接调接口慢几秒**：每次都要启动一次命令行。
- `temperature` 等采样参数不起作用。
- 模型偶尔会在正式回答前写一段草稿。转接口会要求它把正式回答放进 `<answer>` 标签，只把标签里的内容交给面板；
  模型没有照做时，会等它写完再整段给出（这种情况下看不到逐字输出）。

## 安全上的处理

- 只接受本机（回环地址）发来的请求，并且必须带对转接口令。面板后端默认监听所有网卡，
  没有这两道闸，同一个局域网里的人就能借这台电脑的 Claude 账号用。
- 调用命令行时关掉它的全部工具、不加载 MCP 服务、不保存会话，在一个空目录里运行；
  它只能根据发过去的文字生成文字，碰不到本机的文件。
- 同时最多跑 2 个，单次最长 10 分钟；调用方断开时会结束还在跑的进程。
- 转接口令存在 `data/user_data/extensions/claude_bridge/key.txt`，只有本机用户能读。删掉它会重新生成一个。

## 为什么路径不在 `/api/` 下面

OpenAI 的 SDK 会带 `Authorization: Bearer <key>`，而面板把 `/api/` 下的 Bearer 当作它自己的开放接口令牌来验，
会直接拒绝。所以对话接口放在 `/claude-bridge/v1`，由本扩展自己做上面两道校验；
只有给人看的配置说明 `info` 放在 `/api/custom/claude-bridge/` 下，走面板自己的登录校验。
